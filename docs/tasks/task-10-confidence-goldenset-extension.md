# task-10: 신뢰도 골든셋 확장 + Before 측정

- 브랜치: `chore/confidence-goldenset`
- 커밋 타입: `chore:`
- 선행 조건: task-09 머지

## 배경

task-09 기준선에서 **12케이스 전부 `HIGH`** 가 나왔다. 초점이 나가 사람도 물건을 알아보기 어려운 사진에서도 HIGH였다. 결과적으로 task-07의 저신뢰 재분류 분기(`retry`)는 실전에서 한 번도 트리거되지 않고, task-08이 프론트로 내려주는 `confidence`는 항상 HIGH라 "확인이 필요한 초안"을 구분할 수단이 없다.

이 결함을 고치는 건 task-11이다. **이 작업은 고치기 전에 측정 도구를 갖추는 것까지만** 한다.

## 왜 먼저 하는가 (순서 고정)

지금 골든셋에는 LOW가 나와야 마땅한 케이스가 저품질 사진 1건뿐이다. 이대로 고치고 재측정하면 12/12 → 11/12 정도로만 움직여 개선의 증거가 되지 못한다. 그렇다고 수정 후에 케이스를 추가하면 "통과하기 쉽게 맞춘 것 아니냐"를 반박할 수 없다. **케이스 추가와 Before 측정이 수정보다 먼저 머지되어야 한다.**

## 작업 단계

1. `ai-service/eval/golden/cases.json`에 저신뢰 기대 케이스 4~5건 추가 (기존 12건은 **수정 금지**, 총 16~17건)
   - 심한 흐림 / 어두워서 형체만 보이는 사진
   - 물건이 화면 일부만 잡힌 사진 (크롭·부분 촬영)
   - 여러 물건이 섞여 무엇이 매물인지 모호한 사진
   - 카테고리 5종 어디에도 속하지 않는 물건 (예: 악기, 자전거) — 억지로 하나를 고르되 신뢰도는 낮아야 한다
   - 이미지는 기존과 같이 Wikimedia Commons 공개 사진을 쓰고, URL이 응답하는지 확인한다
2. 케이스 스키마에 `expectedConfidence` 추가 — `"HIGH"`(자신 있어야 함) / `"NOT_HIGH"`(MEDIUM·LOW 중 하나여야 함) 두 값만 쓴다. MEDIUM과 LOW를 구분해 요구하지 않는다(모델이 그 경계를 일관되게 지킬 근거가 없다)
   - 기존 12건은 대부분 `HIGH`, 저품질 1건은 `NOT_HIGH`
3. `ai-service/eval/run_eval.py`에 **신뢰도 적중률** 지표 추가 — `expectedConfidence`와 실제 값의 일치율. 기존 지표는 그대로 둔다
4. 확장된 골든셋으로 1회 실행 → `docs/measurements/ai-quality-baseline.md`에 **Before(확장판)** 절을 추가한다. 기존 12건 기준선 수치는 지우지 않고 남긴다
